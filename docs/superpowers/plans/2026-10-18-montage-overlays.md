# Montage overlays implementation plan

> For agentic workers: use subagent-driven-development with scoped implementations and review.

Goal: extend existing montage overlay into multiple numeric, timed, saved layers in the main Editor. User specification is the acceptance authority. No main/PR403/Frozen/EXE changes, no production tests.

Architecture: retain all selection/planning/render engines. A shared validated overlay template is snapshotted into TimelineProject and composed in ONE FFmpeg filtergraph after the selected renderer; disabled templates preserve the existing fast path. Legacy overlay_path remains supported through the same composer, including Remotion (currently silently omitted). All sources local. No third-party code/dependencies required.

Shared contract: template = {version:1, layouts:{'16:9':[layer], '9:16':[layer]}}. Each layer has id,name,enabled,path,kind(image|video),x,y,width,height,keepAspect,opacity,start,duration,mode(once|repeat|end),repeatEvery,endOffset,chromaEnabled,chromaColor(#RRGGBB),chromaSimilarity,chromaBlend,audioEnabled(defaultfalse). Layer array order is bottom to top. Coordinates are output pixels from top-left. Per-layout values independent. Show intervals clipped to total final duration including intro; each video occurrence starts at source0. End mode starts total-endOffset (Nseconds beforeend), limited by duration. Numeric validation rejects invalid/nonfinite/unbounded input, missing enabled files fail visibly.

Settings field montage_overlay_template; public montageSettings.overlayTemplate. Project field overlay_template. New command save-montage-overlays accepts template, scope(new|selected), indices, overwrite(defaultfalse). Default applies only to future queue entries. Selected application skips active tasks, requires overwrite true for existing individualized template, updates saved projects WITHOUT selection, and stores queued-only overrides. Every queue entry snapshots its template so later defaults do not change existing work. New source operations must retain existing settings concurrent-write protection. Independent file writes must use existing locks/atomic publish.
