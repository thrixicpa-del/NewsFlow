# Footage blocks — approved issue417

Owner approved implementation with «делай» after specifying manual editing and render toggle.

## Запрос владельца

В разделе «Индекс» вручную создавать именованные блоки футажей и выбирать для них корневые папки. Пример: блок «Алиев протесты» → папка с заранее собранными подходящими видео. Назначать блоки темам через TXT и сохранять связь по существующему Product ID, по аналогии с ручными промптами в «Обложках».

Это отдельная задача; не добавлять реализацию в PR #403 или #415.

## Ручные блоки в «Индекс»

- Кнопка «Создать блок»: пользователь сам вводит название и выбирает корневую папку. Поддержать несколько независимых блоков без произвольного фиксированного ограничения количества. Не требовать автоматической генерации блоков.
- Показывать название, полный путь и количество доступных видео. Блок можно переименовать, изменить его папку или удалить из настроек; исходные файлы при этом не перемещать и не удалять.
- Блок имеет устойчивый внутренний ID: переименование не разрывает сохранённые назначения темам. Неоднозначные одинаковые имена не разрешать молча. Настройки и связи сохраняются после перезапуска.
- Единая галочка «Использовать блоки футажей при монтаже» явно активирует этот режим для подготовки и рендеринга роликов. Это не переключатель запуска индексации. Включена — для темы брать материалы из назначенного ей блока; выключена — обычный существующий подбор, включая общую библиотеку (~27 тысяч файлов) с учётом текущих настроек источников. Не добавлять противоположную независимую галочку, создающую конфликт режимов.
- Галочку разместить в настройках монтажа/рендеринга, где пользователь запускает сборку; в разделе «Индекс» сохраняется управление блоками. Показать действующий режим и назначенный блок/путь также у темы или задания. Настройка сохраняется после перезапуска и передаётся по существующей цепочке UI → IPC → Electron → Python.
- При выключении галочки блоки и назначения Product ID → блок не удаляются. Их можно заранее создать, импортировать и редактировать, а использовать при монтаже только после включения. Не включать режим скрыто из-за TXT-импорта или смены блока.
- Состояние галочки фиксируется в задании и сохранённом проекте вместе с назначением блока. Изменение настройки не влияет на уже запущенный рендер и не меняет ранее сохранённый проект при простом повторном экспорте. Для ещё не начатой подготовки применяется выбранный режим.
- В активном режиме у темы без назначенного блока явно показывать отсутствие назначения до запуска; не выбирать произвольный блок и не подмешивать общую библиотеку скрыто.
- В режиме блока брать футажи только из назначенной папки, включая её подпапки. Не подмешивать общий индекс или стоки без отдельного явного выбора. Переключение на общую библиотеку сохраняет существующий широкий смысловой подбор.

## Точный TXT-формат, подтверждённый владельцем

Каждый непустой абзац — одно поле; пустая строка разделяет поля. Первый абзац — тема, следующий — название блока, затем новая тема и её блок. Пример:

```text
Заявления Алиева о протестах

Алиев протесты

Политическая ситуация в Армении

Армения политика

Новая история о протестах в Баку

Алиев протесты
```

Три темы, три назначения; один существующий блок может использоваться несколькими темами. Не считать название блока новой темой или промптом обложки. Не требовать повторения темы перед каждым футажом.

- Добавить «Импортировать TXT» в раздел «Индекс». Поддержать произвольное число пар в одном файле без тихого усечения.
- Обработать UTF-8/BOM, CRLF/LF, несколько пустых строк, конечный перевод строки. Нечётное количество непустых абзацев, отсутствующий/неоднозначный блок и конфликтующие назначения показывать до записи.
- Предпросмотр: тема → Product ID → блок → полный путь. Не угадывать Product ID по позиции строки или очереди.
- Однозначная существующая тема сохраняет свой durable Product ID. Для новой темы использовать существующий путь создания ProductionItem, как в #408/#410; одна тема получает один ID, затем её блок, задачи, проект и MP4 остаются привязаны к нему. При нескольких одинаковых названиях тем требуется явное разрешение конфликта, а не случайный выбор.
- Повторный импорт и повторная доставка команды не создают лишние темы/привязки. Ошибка одной пары не должна оставлять частично записанный пакет. Назначение не запускает рендер автоматически.

## Ручное изменение блока у темы

Дополнение владельца: после импорта или ручного назначения пользователь может передумать и выбрать любой другой созданный блок непосредственно у отдельной темы.

- Рядом с темой показывать текущий блок и действие «Изменить блок» с выбором из всех вручную созданных блоков. Отображать название и полный путь, чтобы отличать наборы.
- Ручное редактирование доступно независимо от TXT-импорта: тема может получить первое назначение вручную или сменить уже назначенный блок без повторного импорта файла.
- Привязка сохраняется по неизменному Product ID этой темы. Не создавать новую тему и не менять её сценарий, озвучку, обложки, историю или порядок в очереди. Темы, использующие тот же блок, не должны изменяться вместе с редактируемой темой.
- После сохранения новое назначение видно в UI и сохраняется после перезапуска; следующий ещё не начатый подбор для темы использует выбранный блок. При активном режиме общей библиотеки явно показать, что сохранённое назначение блока вступает в действие в режиме своих блоков; не менять режим скрыто.
- Уже выполняющееся задание сохраняет свой снимок назначения. Готовый проект/MP4 не переделывать автоматически: применение нового блока к уже собранному ролику — явное действие пользователя с повторным подбором только для этой темы. Простой повторный экспорт сохранённого проекта сохраняет прежние выбранные материалы.
- Отмена редактирования ничего не записывает. Не сохранять несуществующий блок или недоступную папку молча. Повторный TXT-импорт с другим назначением для темы не должен без подтверждения затирать её индивидуальный ручной выбор; конфликт показывается до записи пакета.

Приёмка дополнения:

- [ ] Тема после TXT-импорта: сменить блок А на Б вручную, сохранить, перезапустить; Product ID и остальные данные прежние, назначение Б сохранено.
- [ ] Назначить блок вручную теме без предыдущей связи; отменить другое редактирование без изменений.
- [ ] Две темы с блоком А: изменение одной на Б не меняет вторую, включая очередь и асинхронные результаты.
- [ ] Ожидающая задача использует новое назначение; уже запущенная сохраняет прежнее. Повторный экспорт готового проекта не перемешивает и не заменяет футажи.
- [ ] Повторный TXT с конфликтом не затирает ручной выбор без подтверждения; сохранение проверено через UI → IPC → Python → хранилище в изолированном профиле.

## Случайный монтаж из блока и разнообразие

- Для темы с выбранным режимом блока случайно перемешивать доступные пригодные видео её папки и распределять их по существующим сценам и длительности озвучки. Не создавать вторую Story Map и не менять тему/сценарий/тайминги ради выбранных файлов.
- Папка — вручную собранный пользователем тематический набор; случайный выбор должен реально использовать её содержимое, а не постоянно возвращать один наиболее похожий клип из общей библиотеки.
- Сохранять существующий ползунок «Уникальность, %», историю файлов/фрагментов и ротацию. Для похожих тем с одним блоком стараться менять файлы, фрагменты и их положение. Не обещать 100% разных исходников при маленькой папке и не считать стоп-кадр новым материалом.
- Сохранять реально выбранный порядок, исходники/фрагменты и привязку блока в проекте, чтобы повторный экспорт был воспроизводим. Новое перемешивание — явное повторное действие пользователя, не скрытое изменение при каждом экспорте.
- При нехватке длительности сохранять озвучку целиком и применять согласованное автозаполнение в пределах назначенного набора: допустимое повторное использование с учётом уникальности/разрешённое удержание кадра. Если пригодных кадров вообще нет — существующий нейтральный фон и явный статус причины; не подставлять чужую папку и не заявлять полноценное покрытие футажами.
- Отсутствующие, пустые и повреждённые папки/файлы обрабатывать явно. Сохранить паузу/продолжение, прокси-кэш, FFmpeg/NVENC/Remotion, ручные замены, лицензии и текущие аудиоправила. Импорт/переименование блока не запускают повторный анализ всех 27 тысяч файлов.
- Очередь и проект хранят снимок применённого назначения. Изменение блока не меняет уже выполняющиеся задания; индивидуальные назначения/ручные замены не затирать молча.

## Критерии приёмки

- [ ] Создание вручную нескольких блоков, назначение корней, переименование, удаление записи без удаления видео; сохранение после перезапуска.
- [ ] Галочка активации в монтаже/рендеринге: выключена — прежний подбор; включена — назначенный теме блок. Состояние сохраняется после перезапуска и реально применяется на backend, а не только отображается в UI.
- [ ] Отключение не удаляет блоки/назначения, импорт не включает режим сам; смена галочки не меняет запущенные задания и простой повторный экспорт готового проекта.
- [ ] Переключение общая библиотека ↔ свои блоки; изоляция выбранного блока, корректная работа подпапок и канонических путей.
- [ ] Точный TXT-пример выше, большие пакеты, BOM/CRLF/пустые строки, неверные пары, неизвестные блоки, дубли и неоднозначные темы; атомарность и повторная доставка.
- [ ] Правильный Product ID при сортировке/изменении очереди, нескольких одинаково названных темах, перезапуске и асинхронном завершении рендеров.
- [ ] Две похожие темы с одним блоком: разные порядки/исходники при наличии вариантов, сохранённая история и соблюдение уникальности; повторный экспорт не перемешивается заново.
- [ ] Маленькая/пустая/недоступная папка: нет тихого перехода в общую библиотеку, нет сокращения озвучки или ложного отчёта об уникальности.
- [ ] Изолированный реальный UI → IPC → Electron → Python → очередь → проект → MP4. Проверить источники, таймлайн, длительность, повторы и целостность озвучки; не ограничиваться тестом парсера.
- [ ] RED → GREEN для воспроизводимых дефектов; связанные регрессии и применимые FAST/SYSTEM/контрактные/CI/Windows gates по AGENTS.md. FAIL/UNKNOWN/NOT RUN сохранять явно.
