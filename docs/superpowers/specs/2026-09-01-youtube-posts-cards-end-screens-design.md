# Автоматические публикации, подсказки и конечные заставки

## Цель

После загрузки и назначения времени ролика NewsFlow должен автоматически
подготовить на том же канале все связанные элементы: запись сообщества,
подсказки и конечную заставку. Каждый канал использует только собственный
NewsFlow Chrome-профиль с уже выполненным входом в Google.

## Границы

- Видео продолжает загружаться через YouTube Data API и назначается через
  существующую очередь публикаций.
- Записи сообщества, подсказки и конечные заставки выполняются через
  YouTube Studio в выделенном профиле канала. У YouTube Data API нет методов
  создания этих элементов.
- Исполнитель не читает, не экспортирует и не переносит cookies, пароли или
  сессии между профилями. Он открывает только профиль, уже созданный
  NewsFlow для соответствующего канала.
- Расширение ChatGPT не является зависимостью приложения. Оно нужно только
  для ручного управления браузером из чата.

## Политика на один ролик

Для успешно загруженного ролика с заданным `publishAt`:

1. **Запись сообщества.** Создать одну запись с прикреплённым роликом,
   текстом из SEO-описания без хэштегов и тем же `publishAt`.
2. **Подсказки.** Добавить до двух видеокарточек: на 35% и 65% длины ролика.
   Цель выбирается из уже опубликованных подходящих роликов того же канала:
   сначала тематически похожий, затем последний опубликованный. Если подходящего
   ролика нет, карточка пропускается. Текущий и непубличные ролики не выбираются.
3. **Конечная заставка.** На последних 20 секундах ролика (только если длина
   не менее 25 секунд) установить: тематически похожий предыдущий ролик,
   «лучший для зрителя», подходящий публичный плейлист и подписку. Недоступные
   элементы пропускаются, случайные видео не подставляются.

Карточки не ставятся в последние 20 секунд, так как в этой зоне YouTube
подавляет их показы. Политика намеренно использует два из допустимых пяти
карточек и до четырёх элементов конечной заставки.

## Данные и состояния

Поле `post` у задания публикации расширяется результатами браузерного
исполнителя: `pending`, `running`, `scheduled`, `failed`, `skipped`, датой
запуска, временем планирования, URL поста при наличии и текстом ошибки.

Добавляется отдельный объект `engagement`:

- `cards`: целевые видео, временные позиции и итоговый статус каждой карточки;
- `endScreen`: выбранные элементы, время начала и итоговый статус;
- `attempts`: ограниченный журнал запусков без токенов, cookies и содержимого
  профиля.

Для каждого канала хранится собственная политика с включателями постов,
подсказок и конечных заставок. Значения по умолчанию соответствуют этой
спецификации.

## Исполнитель Studio

После API-загрузки задача добавляется в фоновую очередь канала. На один
Chrome-профиль допускается только один активный исполнитель. Он:

1. открывает Studio с идентификатором назначенного канала;
2. проверяет, что сессия и канал совпадают с заданием;
3. создаёт/планирует пост, затем настраивает карточки и конечную заставку;
4. после каждого атомарного шага сохраняет состояние задания;
5. при повторном запуске продолжает только незавершённые шаги и не создаёт
   дубликат поста или элементов.

Если вход истёк, канал не совпадает, интерфейс Studio изменился или ролик ещё
не доступен для нужного элемента, исполнитель завершает шаг состоянием
`failed` или `skipped` с понятной причиной и кнопками «Открыть профиль» и
«Повторить». Закрытие Chrome не считается успешным завершением задачи.

## Интерфейс

В карточке задания публикации отображаются три независимых статуса:
«Пост», «Подсказки», «Конечная заставка». Кнопки: «Повторить неудачные»,
«Открыть профиль канала», «Отключить автоправило для канала». Планировщик
показывает время поста вместе со временем видео.

### Разделы приложения

Аналитика, публикация, умное распределение и автоправила являются разными
разделами боковой навигации. Ни один из них не прячет ключевые действия в
длинной единой форме.

1. **Аналитика.** Вверху — фильтры: все каналы или выбранные каналы, текущий
   месяц, прошлый месяц, последние 30 дней, последние 90 дней и произвольный
   период. Отдельный фильтр показывает только каналы с подключённым доходом,
   без дохода или все. Под фильтрами — сетка-калькулятор: число каналов,
   просмотры, подписчики, публикации, часы просмотра и доход. Значения
   суммируются только из каналов и периода, которые попали в фильтр; доход
   показывает «нет доступа», а не ноль, если OAuth не дал финансовые данные.
   Ниже — динамика по выбранному периоду и таблица каналов с деталями.
2. **Публикация.** Очередь готовых роликов с миниатюрой, длительностью,
   каналом, временем и статусами поста/подсказок/конечной заставки. Оператор
   выбирает один или пачку роликов чекбоксами, назначает их на один или
   несколько каналов, переносит карточки между каналами и применяет время
   вручную либо сеткой.
3. **Умное распределение.** Отдельный экран предпросмотра до применения:
   самые длинные нераспределённые ролики идут сначала на каналы с включённой
   монетизацией, остальные — на другие совместимые каналы. При равной длине
   используется стабильный порядок очереди. Пользователь может снять ролик
   из рекомендации или вручную перетащить его до подтверждения.
4. **Автоправила.** Настройки и журнал выполнения для постов, подсказок и
   конечных заставок отдельно для каждого канала.

### Визуальная система

Интерфейс использует короткие названия действий, крупные кнопки и заметные
цветовые роли: основное действие — синий, успешная операция — зелёный,
ожидающее внимание — янтарный, опасное/удаление — красный. Цвет всегда
сопровождается иконкой и текстом. Сложные параметры скрываются в
«Расширенных настройках», а в основном сценарии остаются только выбор
роликов, каналов, времени и запуск.

## Проверки

- unit-тесты выбора предыдущего релевантного ролика, позиций карточек,
  исключения текущего/непубличного видео и сериализации состояний;
- unit-тесты идемпотентного восстановления очереди после перезапуска;
- тесты bridge-команд и snapshot для отображения статусов;
- unit-тесты аналитического агрегатора: текущий/прошлый месяц, произвольный
  период, фильтры каналов, частично недоступный доход и суммарные счётчики;
- unit-тесты умного распределения: самые длинные ролики сначала получают
  монетизированные каналы, ручное назначение не перезаписывается;
- UI-тесты массового выбора, ручного переноса, состояния кнопок и видимых
  фильтров в отдельных разделах;
- тестовый browser-adapter с подменёнными элементами Studio, включая истёкшую
  сессию и отсутствие подходящих роликов;
- ручная проверка в тестовом канале: один ролик, один пост, две карточки,
  конечная заставка и отсутствие дубликатов после повторного запуска.

## Критерии готовности

- Успешно загруженный запланированный ролик автоматически получает пост на то
  же время, без хэштегов в тексте и с прикреплённым роликом.
- Для подходящего длинного ролика появляются две карточки и конечная заставка
  согласно политике.
- Каждый канал работает только в своём профиле, без требования расширения
  ChatGPT.
- Ошибка одного шага не скрывается, не блокирует отображение ролика и не
  приводит к повторной публикации при перезапуске.
- Аналитика корректно показывает сводные значения за текущий месяц, прошлый
  месяц и любой выбранный период, а недоступный доход не подменяется нулём.
- В публикации можно вручную выбрать пачку роликов, разнести её по каналам и
  до применения увидеть предложение, где длинные ролики направлены на
  монетизированные каналы.
