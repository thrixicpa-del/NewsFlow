# NewsFlow — центр публикации YouTube

## Цель

Добавить в NewsFlow самостоятельный раздел **«Публикация YouTube»**. Он принимает готовые пакеты роликов из производственного конвейера, подключает принадлежащие пользователю каналы через Google OAuth, планирует загрузки, показывает проверяемую аналитику и предоставляет управляемые агентные задачи.

## Принятые решения

- Подключение каждого канала выполняется через Google OAuth для desktop-приложения. NewsFlow не получает и не хранит пароль Google.
- OAuth client JSON пользователь добавляет в приложении; доступ к каждому каналу подтверждается отдельно в системном браузере.
- Токены обновления хранятся только локально, защищённо текущей учётной записью Windows; отключение канала удаляет его токен из NewsFlow.
- Кнопка **«Открыть YouTube Studio»** открывает Studio выбранного канала одним кликом. Это удобный ручной вход, а не замена OAuth.
- У задачи без даты и времени режим по умолчанию — **приватный черновик**. Для задачи и пресета пользователь может выбрать `private`, `unlisted`, `public-now` или `scheduled`.
- Публикация роликов собственных каналов допускает выполнение по правилам очереди. Агент «Прогрев» не имитирует человека: он готовит наблюдения, подборки и черновики, а публичные лайки/комментарии требуют отдельного подтверждения пользователя.

## Информационная архитектура

В боковой навигации раздел «ПУБЛИКАЦИЯ» получает новый первый пункт:

```text
Публикация YouTube
├─ Обзор
├─ Очередь публикаций
├─ Каналы
├─ Аналитика
├─ Прогрев
└─ Журнал действий
```

Существующие SEO-пакеты, теги и результаты сохраняются как самостоятельные экраны. «Публикация YouTube» связывает их в один конечный пакет, но не дублирует их данные.

### Обзор

- Видимые счётчики: готово к отправке, сегодня, запланировано, загружается, требует внимания.
- Ближайшие публикации отображаются временной лентой по локальному часовому поясу пользователя.
- Карточки «канал растёт» показываются только если вычисление основано на сохранённых измерениях; у карточки всегда есть пояснение, какие метрики дали сигнал.
- Основное действие: «Добавить готовые ролики в очередь».

### Очередь публикаций

Единица очереди — `PublicationJob`. Она создаётся из готового пакета NewsFlow: MP4, выбранная обложка, сценарий, SEO-описание, теги и хэштеги.

Поля задачи:

- канал;
- исходный MP4 и контрольный размер/длительность;
- исходное название сценария — это заголовок YouTube по умолчанию;
- SEO-описание, ключевые SEO-фразы, теги, хэштеги, обложка;
- видимость; дата и время; локальная временная зона;
- статус и подробная временная линия;
- повторная попытка и причина последней ошибки;
- ссылочный ID ролика YouTube после успешной загрузки.

Статусы:

```text
ready → scheduled → uploading → processing → awaiting-publication → published
                  ↘ failed / cancelled / needs-attention
```

Очередь поддерживает массовое назначение канала, времени, видимости и пресета. Пресет включает диапазоны времени, лимит роликов в день и правила разнесения между публикациями.

При добавлении из «Результатов» NewsFlow связывает поля так: имя сценария — с исходным сценарием, заголовок/описание/SEO-фразы/хэштеги — с SEO-пакетом, теги — с очередью тегов, обложка — с оставленным вариантом галереи. Если часть пакета отсутствует, задача помечается «требует заполнения», а не отправляется с молчаливой пустой метаинформацией.

Название сценария становится исходным заголовком ролика. Перед постановкой в upload NewsFlow проверяет лимит YouTube в 100 символов. Если название длиннее, агент перефразирует его до 100 символов, сохраняя структуру и смысл исходного заголовка; оригинал и новый вариант показываются оператору. При недоступности агента или неудачном результате задача получает состояние «требуется заголовок» и не отправляется в API с заведомо недопустимым названием. SEO-заголовок остаётся подсказкой для агента, но не заменяет исходное название без явного решения оператора.

#### Сетка для множества каналов

Пресет «Сетка публикаций» принимает: список каналов, начало и конец окна, период **в минутах** (например 60, 180 или 240), число публикаций на канал, минимальную дистанцию между задачами, временную зону и метод распределения. Например, для 100 каналов, начала в `04:00` и периода `3 часа` NewsFlow создаёт циклы, пока время старта очередной публикации попадает в заданное окно.

Метод распределения выбирается оператором:

- **Равномерно** — назначает стабильные смещения внутри интервала, насколько это возможно; это снижает одновременные старты, но не запрещает их.
- **Совпадения разрешены** — ролики разных каналов могут выходить в одну и ту же минуту, если так задано правилом или плотностью сетки.
- **Синхронно** — все выбранные каналы получают одни и те же точки времени.
- **Ручной/смешанный** — оператор двигает отдельные карточки, фиксирует их или массово сдвигает дни/каналы; затем NewsFlow пересчитывает только незаблокированные задачи вокруг новых правил.

Таким образом, правило «каждые 3–4 часа» или «каждый час» задаётся напрямую и не меняется попыткой искусственно сделать все каналы уникальными. Смещения и ручные блокировки хранятся с пресетом, поэтому перезапуск NewsFlow не переставляет уже назначенные ролики. В предпросмотре видно, где время совпадает, и можно задать любую минимальную дистанцию — включая ноль.

Ролики будут загружаться заранее как приватные, а YouTube получает время `publishAt`; поэтому опубликование по времени не зависит от того, открыт ли NewsFlow в момент выхода. В интерфейсе будет виден отдельный статус «загружен, ждёт времени публикации».

YouTube накладывает проектные лимиты загрузок. Раздел будет считать требуемое число загрузок в сутки и заранее показывать нехватку подтверждённой квоты. Для примера с 100 каналами и шестью роликами в день нужно 600 uploads/day, что нельзя молча обходить несколькими проектами: потребуется легитимно запросить достаточную квоту у Google.

### Каналы и OAuth

Карточка канала отображает:

- имя, изображение и channel ID после OAuth-подключения;
- OAuth: «не подключён», «подключён», «нужно переподключить»;
- доступные возможности: публикация, базовая аналитика, финансовая аналитика;
- подписчики, последние измерения и индикатор наличия финансовых данных;
- кнопки «Подключить через Google», «Открыть Studio», «Обновить», «Отключить».

Для работы понадобятся включённые в проекте Google Cloud API: YouTube Data API v3, YouTube Analytics API и YouTube Reporting API. Publishing использует scope `youtube.upload`; аналитика и готовые отчёты — `yt-analytics.readonly`; финансовые показатели запрашиваются отдельно через `yt-analytics-monetary.readonly`, чтобы не требовать этот доступ, если пользователю он не нужен.

Монетизация не выводится догадкой. Если доступен доход или рекламные метрики, интерфейс показывает «финансовые данные доступны». Если API не выдаёт их — «нет финансовых данных», без вывода о подключённой или отключённой монетизации.

### Аналитика

Данные делятся на три уровня:

1. **Снимки NewsFlow** — периодические локальные измерения публичных счётчиков по подключённым каналам и роликам. Они дают честный график «за 48 часов» и расчёт просмотров в час.
2. **YouTube Analytics** — просмотры, время просмотра, удержание, реакции, подписчики, показатели по роликам, источникам и темам. Запросы выполняются только для каналов, разрешённых OAuth.
3. **Финансовые данные** — estimated revenue, CPM и монетизированные воспроизведения при отдельном согласованном scope и фактической доступности данных у канала.
4. **YouTube Reporting API** — ежедневные объёмные CSV-отчёты, которые NewsFlow скачивает и обновляет как историю: по ролику, дню, стране, источнику трафика, устройству, месту воспроизведения и статусу подписки зрителя. Они не заменяют быстрые снимки, потому что появляются с задержкой около суток.

Экран «Аналитика» отделён от очереди публикаций и начинается с фильтров: **все каналы / один канал / сохранённая группа**, период **1 час, 24 часа, 48 часов, 7 дней, 28 дней или 30 дней**, а также выбор показателей. Для всех каналов сводка агрегирует доступные данные: просмотры, просмотры в час, прирост подписчиков, публикации и **суммарный доход за 30 дней**. При выборе одного канала те же графики и таблицы показывают только его данные.

Графики будут показывать фактические ряды, а не декоративные числа: просмотры по часам, накопленные просмотры, прирост подписчиков, число публикаций и доход при финансовом OAuth-доступе. У каждого графика будет источник, период, последний момент обновления и понятное пустое состояние. Если хотя бы один канал не даёт финансовые метрики, итог по доходу помечается как «по каналам с доступом», а не выдаётся за полный доход сети. Карточка «потенциал роста» не обещает результат: она объясняет обнаруженный сигнал (например, ускорение просмотров относительно последних измерений того же канала).

Полный экран одного канала состоит из цветных карточек (просмотры, время просмотра, средняя длительность, удержание, прирост/отток подписчиков, реакции, доход/CPM при доступе), графиков и раскрываемых таблиц. Вверху — **библиотека роликов**: настоящая миниатюра YouTube, заголовок, дата и время выхода, статус видимости/обработки, длительность, просмотры, реакции, комментарии, описание, теги, ссылка на ролик и на Studio. Для роликов, опубликованных NewsFlow, карточка дополнительно показывает сценарий, SEO-пакет, выбранную обложку, задачу очереди, статус поста и отметку загрузки. Таблицы фильтруются по периоду и ролику: **ролики**, **источники трафика**, **страны**, **устройства и ОС**, **места воспроизведения**, **аудитория и подписка**, **доход по роликам/странам**. Сводка всех каналов использует те же показатели, но не смешивает отсутствующие финансовые данные с нулём. В каждой секции видны источник (быстрый снимок, Analytics или Reporting), дата последнего отчёта и причина отсутствия доступа.

### Агент «Прогрев»

Запуск выбирает один, несколько или все каналы. Задача агента:

- собрать новые ролики выбранных каналов, их темы и открытые показатели;
- отметить изменения активности и представить их в журнале;
- предложить релевантные темы, форматы, ролики для просмотра и черновики комментариев;
- не ставить лайки, не оставлять комментарии и не совершать другие публичные действия автоматически.

В интерфейсе есть фильтр «Все каналы / выбранные», кнопки запуска и остановки, статус текущего прогона, отчёт по каждому каналу и список черновиков. Пользователь сам принимает либо отклоняет любой подготовленный текст или действие.

### Журнал

Каждая загрузка, изменение расписания, OAuth-ошибка, обновление аналитики и запуск «Прогрева» сохраняются в локальном журнале с временем, каналом, объектом и понятной причиной. Журнал не хранит OAuth-секреты.

## Дизайн

Страница ориентирована на оператора новостного конвейера: тёмная база NewsFlow остаётся, а у публикации появляется спокойный акцент цвета янтарного сигнала — он обозначает ожидающее решение или запланированное событие, но не ошибки.

Палитра:

- `#071523` — глубокий фон;
- `#0E2338` — поверхность карточек;
- `#1D4264` — границы и оси графиков;
- `#55D6A2` — подтверждённое/опубликованное;
- `#F5B942` — расписание и ожидание;
- `#F06B7A` — ошибка/требуется действие.

Уникальный элемент страницы — «линия эфира»: тонкая горизонтальная временная шкала ближайших публикаций, где каждая задача является фактическим блоком времени, а не декоративной полосой. Она связывает очередь, статус обработки и открытие Studio.

## Техническая архитектура

Новый модуль ядра: `scriptor/youtube_publisher.py`.

Его зоны ответственности:

- хранение и защита токенов каналов;
- OAuth flow desktop-приложения через системный браузер и локальный callback;
- запросы к YouTube Data/Analytics API;
- резюмируемая загрузка MP4 и состояние обработки;
- локальная очередь и scheduler;
- сбор снимков метрик;
- расчёт аналитических производных;
- журнал и данные «Прогрева».

`config.py` хранит сериализуемые настройки и метаданные задач без незашифрованных токенов. `bridge.py` предоставляет явные команды UI. React получает новый тип snapshot `publication` вместо расширения старой неопределённой структуры `channels`.

Для сетевых вызовов предпочтительны официальные Google client libraries с ограниченными scope. Транспорт, часы и API-клиент инъецируются в модуль, чтобы тесты не обращались к Google.

## Этапы реализации

1. Модели данных, миграция старых карточек каналов, локальная очередь, журнал и тесты.
2. Новый экран «Публикация YouTube»: готовые пакеты → очередь, сроки, пресеты, статусы и Studio.
3. OAuth и API-клиент, подключение канала, обновление профиля, безопасное хранение токенов.
4. Загрузка/повтор/планирование и отслеживание обработки роликов.
5. Снимки, аналитические запросы, 48-часовой график, финансовые данные и сигналы роста.
6. Раздел «Прогрев» с отбором каналов, журналом и черновиками действий.
7. Реальная проверка на тестовом OAuth-канале и собранном приложении после получения OAuth JSON.

## Проверка

- модульные тесты для переходов статусов, расписания, диапазонов, пресетов, миграции и защиты токенов;
- тесты bridge-команд и формы snapshot;
- UI-тесты для добавления готовых роликов, массового назначения, удаления и истории;
- API-клиент тестируется на фикстурах Google-ответов, без реальных учётных данных;
- после получения OAuth JSON: ручный вход, выбор канала, открытие Studio, загрузка тестового приватного ролика, проверка обработки и обновления аналитики;
- публикация не становится публичной в тесте без явного выбора пользователя.
