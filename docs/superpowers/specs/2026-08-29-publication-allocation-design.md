# Конструктор распределения роликов по каналам

## Цель

NewsFlow должен превращать пул готовых роликов в проверяемый план публикации
для сети каналов. Оператор видит, сколько роликов требуется создать, какие
конкретно ролики назначены каждому каналу, какие остаются в резерве и каких
не хватает. План переживает перезапуск приложения.

## Правила количества роликов

У канала есть сохранённый профиль публикации. Базовое предложение вычисляется
по последней фактической аналитике и не меняет сохранённый план, пока оператор
не нажмёт «Применить рекомендации».

Приоритет правил строгий:

1. Канал с подтверждённым доступом к монетизации получает **3 ролика** за
   выбранный цикл.
2. Немонетизированный канал с сигналом роста (ускорение просмотров и
   положительный прирост подписчиков относительно его прошлых измерений)
   получает **2 ролика**.
3. Обычный или новый канал получает **1 ролик**.
4. Вручную заданный лимит блокирует автоматическое изменение, пока оператор
   явно не снимет блокировку.

Профиль также хранит допустимый диапазон длительности, приоритет и роль.
Например, новым каналам подходят короткие ролики, а монетизированным —
длинные. Диапазоны и лимиты являются частью пресета и могут быть любыми.

## Конструктор

Экран «Публикация YouTube» получает отдельную секцию «Конструктор выпуска».

В верхней строке показываются фактические счётчики выбранного пресета:

- **Нужно** — сумма лимитов выбранных каналов;
- **Готово** — количество готовых пакетов, подходящих по длительности и
  статусу;
- **Назначено** — число роликов, уже распределённых;
- **Не хватает** — `max(нужно − назначено, 0)`;
- **Резерв** — готовые, но пока не назначенные ролики.

Таблица каналов содержит изображение, название, подписчиков, монетизацию,
сигнал роста, рекомендованный и ручной лимит, диапазон длительности и список
назначенных роликов. У каждого ролика показаны миниатюра, название, длительность,
статус, SEO/обложка и назначенный слот. Оператор может переместить ролик между
каналами, изменить лимит, выбрать роль, назначить или снять назначение.

Кнопка **«Обновить рекомендации»** получает свежие фактические метрики из
подключённых каналов и пересчитывает только предложенные лимиты/сигналы. Она
не меняет уже назначенные ролики. Кнопка **«Применить рекомендации»** меняет
только незаблокированные лимиты. Кнопка **«Сохранить пресет»** хранит весь
набор правил для выбранной группы каналов.

Автораспределение сортирует ролики сначала по соответствию диапазону
длительности, затем по готовности метаданных и приоритету канала. Неподходящий
ролик не выдаётся за подходящий: он остаётся в резерве с понятной причиной.

## Связь с генерацией идей

Счётчик «Нужно» передаётся в «Генерацию идей» как целевой объём нового
выпуска. Вверху страницы идей появляется виджет, например: «Для текущего
пресета нужно 90 роликов; назначено 84; создать ещё 6 тем». При создании тем
NewsFlow не выбирает молча канал, но показывает, для каких каналов/слотов
нужны темы. После готовности ролика конструктор может предложить слот по его
длительности.

## Сохранение и новый выпуск

Сохраняются: профили каналов, лимиты, диапазоны длительности, блокировки,
пресеты, назначенные ролики, черновая сетка и дата последнего пересчёта.

Кнопка **«Новый выпуск / очистить производственную очередь»** находится в
начале генерации идей. После отдельного подтверждения она очищает только
производственные данные: темы, сценарии, очередь озвучки, монтажные задачи,
пакеты результатов, назначения конструктора и черновую сетку. Она не удаляет
файлы с диска, каналы, OAuth-токены, API-ключи, историю аналитики, роли
каналов и сохранённые пресеты. Удаление физических MP4 остаётся отдельным
явным действием в разделе результатов.

## Ошибки и проверка

- при отсутствии длительности ролик помечается «нужно определить длительность»
  и не автонзначается;
- при отсутствии OAuth или аналитики канал сохраняет ручной лимит, но не
  получает ложную метку монетизации/роста;
- если слотов больше, чем готовых роликов, счётчик показывает точную нехватку;
- если готовых роликов больше, лишние остаются в резерве;
- новый выпуск не очищает настройки и токены.

Тесты покрывают приоритет `монетизация=3 → рост=2 → обычный=1`, ручную
блокировку, расчёт счётчиков, соответствие диапазонов длительности,
сохранение/восстановление конструктора и безопасную очистку производства.
