## Использование

В «Обложках» нажать **«Добавить несколько промптов»**. Вставить текст или загрузить TXT:

```text
Тема: Сад

Первый готовый промпт

Второй готовый промпт

Тема: Хлеб

Первый промпт следующей темы
```

Новая тема начинается строкой `Тема: название` (также `Topic:`). Точное название уже существующей темы может стоять без маркера. Каждый следующий абзац — отдельный промпт, переносы строк внутри абзаца сохраняются. Режим «Только промпты одной выбранной темы» принимает одни промпты и связывает их с выбранным Product ID. Прежний режим пар строк сохранён отдельно и явно обозначен как замена одного промпта.

**«Проверить привязку»** показывает темы, Product ID, номера, тексты и уже сохранённые варианты. Изменение ввода/режима/темы сбрасывает подтверждение; изменение очереди отклоняет устаревший token. **«Добавить в обложки»** сохраняет набор без обращения к провайдеру. Новые темы получают один durable ID, все их варианты — собственные устойчивые ID и последовательные номера. Повторная отправка того же текста не создаёт дубли. Новые варианты продолжают нумерацию и не сбрасывают выбранный промпт, картинку или готовые результаты. Во время активной генерации запись отклоняется с сохранением ввода.

Галочка **«Только недостающие варианты — готовые сохранить»** доступна в основном разделе и сохраняется после перезапуска. С ней обычный запуск обрабатывает только ручные варианты без исправного результата. Без неё запускает все ручные промпты, добавляя новые изображения; прежние файлы и выбор остаются. Имена новых файлов включают Product ID, номер варианта и ID запуска. Результат/история несут Product ID, variant ID и номер, а не только позицию очереди. Число 1–10 в прежней настройке ограничивает создание промптов ИИ, не ручной импорт; тестом проверено 125 многострочных вариантов. Существующий лимит TXT 1 МБ сохранён с явной ошибкой и предложением разделить файл, без тихого усечения.

## Причины и исправления

Старый парсер удалял пустые строки, разбирал строго пары и отклонял одну тему с разными промптами как CONFLICTING_DUPLICATE. Запись заменяла image_prompt_options одним вариантом. Новый явный mode=blocks в существующем IPC вызывает отдельный чистый парсер и additive copy-on-write план до записи. Метаданные manual_prompt_schema=1 добавляются только изменяемой тестовой/пользовательской строке, существующие JSON/старые поля остаются совместимы. Неоднозначные ID/темы и повреждённые номера отклоняются до мутации.

Очередь раньше считала всю тему готовой по одной картинке. Для нумерованных ручных вариантов завершённость теперь определяется по привязанным исправным файлам. Очистка/ручная замена/переписывание ИИ удаляют старые active manual metadata; удалённые варианты не возвращаются при следующем импорте. Выбор промпта разрешается по Product ID после перестановки очереди.

Независимое review нашло и закрыло связанные дефекты: старые manual metadata после AI rewrite; потерю provider-контрактов при добавочном рендере; неправильную нумерацию в repeat-current; потерю старых картинок/variant ID после GET-восстановления принятой FastGen задачи. Все воспроизведены регрессиями. Принятая задача блокирует новый create до восстановления. Смешанные per-variant режимы/референсы в repeat-current отклоняются **до удаления любых файлов** по всему выбранному пакету; обычный запуск без галочки остаётся доступен. Ревью окончательной поправки: без оставшихся замечаний.

## Ограничения и границы

Рабочий NewsFlow не останавливался/не изменялся. Все операции хранения, reset и генерации — disposable-профили; сеть и платный text/image provider в offline integration запрещены. Новых original footage анализов нет. Docker NOT RUN: отсутствует dockerDesktopLinuxEngine pipe. Frozen/EXE/lock refresh, packaged/clean Windows, real paid-provider acceptance NOT RUN по границам. MP4 N/A: задача касается промптов и PNG, монтаж не меняется. Исторические integrity FAIL/writer UNKNOWN из #408/#403 не сняты новыми guard PASS.

Задача реализована в source, но готовность к merge/release не объявляется из-за Frozen FAIL и непроверенных RELEASE-уровней. Issue не закрывается, main не изменяется, PR не сливается. Для запуска новой функции в установленной Frozen-версии потребуется отдельная разрешённая сборка.
